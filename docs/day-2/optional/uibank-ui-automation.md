# Optional Lab B: UI Automation on the UiBank Loan Application

## Business context

Plenty of real applications have no usable API, so the only way in is
through the screen. That's the classic UI automation case. This lab asks
your coding agent to build a workflow that fills in and submits a loan
application on **UiBank**, a practice web application, and shows you the one
thing that trips almost everyone up: the agent has to capture selectors
from a real browser.

## Learning objective

Build, validate, and run an RPA workflow generated by a coding agent, and
learn how to unblock it when it can't capture selectors.

## What you'll build

An RPA workflow, in a project called "UiBank Demo", that opens the UiBank
loan application page, fills the form, and submits it.

## Prerequisites

- The [common checklist](index.md#before-you-start-any-of-them) is done
- **Studio Desktop** with the built-in terminal panel, or VS Code. The
  terminal panel needs a recent release from the **STS** channel (the LTS
  channel was too old in the delivery sessions)
- UiPath Assistant signed in to the right organization and tenant
- The UiBank URL from your coach
- A local project folder you can write to. Use a plain local folder, not a
  OneDrive-synced one, which broke Git integration for one attendee

## Estimated duration

About 60 minutes. Budget extra for selector troubleshooting.

## Products and tools used

Your coding agent · Studio Desktop (terminal panel) or VS Code · UiPath
CLI and the RPA skill · Orchestrator

## Exercise: Build the loan application workflow

### Objective

Get a workflow that submits a UiBank loan application end to end, with
working selectors and error handling.

### Starting point

An authenticated coding agent and an empty folder for the project.

### Build steps

1. **Create the project.** In Studio Desktop, create a new project named
   "UiBank Demo" in your local folder. Studio installs only the basic System
   activities by default.

2. **Install the UI Automation package yourself.** Open **Manage Packages**,
   search the Official feed for the UI Automation package, and install it.
   Doing it up front saves the agent time and tokens.

3. **Open your coding agent.** Use Studio's terminal panel, or open the same
   project folder in VS Code.

4. **Sign in first.** Run `uip login` with the explicit form from
   [Environment Setup](../../day-1/2-environment-setup.md) and check the
   org and tenant it echoes back.

5. **Write a short, specific prompt** with the URL, the project folder, and
   the target:

   ```text
   Create an RPA workflow to submit a loan application via UiBank at
   <UiBank URL>. Create it in this project folder. Deploy to this
   organization: {{ training_url }} and tenant: {{ training_tenant }}.
   ```

6. **Watch what the agent plans.** Even without Plan Mode it tends to list
   tasks: check the UI prerequisites, read the UI automation guide, capture
   the loan form's targets, build the workflow, then validate and build.

7. **Let it open the browser** and capture selectors. This is the same job
   you'd do by hand as a developer.

8. **If selectors are missing,** use the fix below. Some attendees saw blue
   placeholder activities with no selector, or a "tool call was rejected"
   message.

9. **Validate and run** the workflow in Studio and confirm the application is
   submitted.

10. **Read the generated workflow.** Agents have been seen adding a
    try/catch with a log message and a rethrow on failure, and a log entry on
    success. Check yours does too.

11. **Optionally publish it** to a folder using Studio's terminal panel.

### Checkpoint

- [ ] The project builds and validates with no errors
- [ ] Every activity that touches the page has a selector
- [ ] A run submits the loan application and you can see the result
- [ ] The workflow handles failure with try/catch and a log message

### Expected output

An RPA workflow that submits the form and a run log showing the application
was submitted. Some attendees finished faster in VS Code than in Studio's
own terminal panel, so don't read much into who finishes first.

!!! warning "Needs validation"
    The UiBank URL was shared in chat during the sessions and never
    spoken, so it must come from your coach. The minimum Studio Desktop
    version for the terminal panel was also unclear across sessions. If the
    panel isn't there, use VS Code instead.

### Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Activities exist but selectors are missing, or a tool call is rejected | The agent is working in a sandboxed browser and can't reach the real page | Tell it: "Don't use the sandbox. Use my local browser to capture the selectors." Then: "The selectors are missing, please update them accordingly." |
| Agent keeps trying to install the UI Automation dependency | Package not installed, or CLI can't be found in that terminal | Interrupt it, install the package yourself in Manage Packages, and check `uip --version` in that terminal |
| Agent goes off searching public repositories for the page's source | It couldn't open the browser | Interrupt it (Esc), then tell it to use the local browser |
| Nothing works until you sign in | Studio isn't signed in to the right tenant | Open UiPath Assistant, sign in to the correct org, then select the folder in Studio |
| Project won't connect to Git | Project was created in a OneDrive-synced folder | Recreate it in a plain local folder |
| Published, but the job won't run ("no runtime available") | No machine or license to run it on | A separate setup step. Ask your coach |
| Agent edits files you didn't expect | It was allowed to change code freely | Use Plan Mode, and tell it exactly which files it may touch |

### Extension challenge

Make it data-driven. Ask your agent to read applicant details from a small
Excel file and submit one application per row, logging a result for each.

### A practical note

For a simple form, recording it yourself and then asking the agent to make
the selectors more reliable can be faster than having the agent build the
whole thing. Agents do well at generating prompts and apps, and are slower
and less predictable at building RPA from scratch. Knowing when to do the
simple part by hand is part of being the expert in the loop.
